# 비공개 실이미지 Phase 6 검증

## 범위와 보안

2026-07-21에 사용자가 제공한 `1920×1080` PNG 한 장을 로컬에서 검증했다.
이미지는 가로 2-up 화면 캡처이며 회색 워터마크, 작은 본문, 표와 표 옆 본문을
포함한다. 원본과 OCR 중간 결과는 `.gitignore`의 `output/` 아래에만 두었고,
저장소·GitHub 이슈·이 문서에는 원문 내용이나 이미지를 포함하지 않았다.

이 샘플에는 정답 Markdown이 없으므로 CER/TEDS 같은 정량 정확도는 계산하지
않고, 사용자가 보고한 실패 유형의 개선 여부를 항목별로 확인했다.

## 비교 결과

| 처리 | 관찰 결과 |
| --- | --- |
| `conservative` | 전체 본문은 비교적 안정적이나 워터마크 겹침 줄과 일부 번호 줄 누락 |
| `off` | 겹침 줄 일부가 보였지만 워터마크 간섭으로 전체 정확도 저하 |
| 임계값 150 + 2배 확대 | 부분 crop에서 겹침 줄 회수가 가장 안정적 |
| Phase 6 `text-safe` | 무채색 이진화·확대 후 원문 OCR 좌표를 보조 사용해 누락 구조 복구 |

`text-safe`는 색상 픽셀을 유지하고 무채색만 이진화한다. PP-Structure가 만드는
Markdown에서는 일반 OCR에 존재하는 줄도 누락될 수 있어, 이 모드에서만 일반
OCR 좌표를 함께 저장한다. 구조 결과에 없는 괄호형 번호 문단과 Note 줄만 원래
순서에 삽입하며 기존 번호는 중복하지 않는다.

## 최종 확인

- 입력 1장으로 출력 2쪽 생성
- 워터마크 겹침 구간의 Note 및 두 전압 관련 줄 회수
- 두 번째 쪽의 번호 1–11 존재, 기존 누락 번호 5·7·10 복구
- `3)`가 Markdown renderer에서 `3.`으로 바뀌지 않도록 `3\)`로 저장
- 표 옆 본문이 다섯 번째 병합 셀 또는 병합 셀 옆 셀로 흡수된 두 경우 모두
  본문을 표 밖으로 이동
- 전체 자동 테스트 50개 통과
