# 비공개 실이미지 Phase 6·7·8 검증

## 범위와 보안

2026-07-21에 사용자가 제공한 `1920×1080` PNG 한 장을 로컬에서 검증했다.
이미지는 가로 2-up 화면 캡처이며 회색 워터마크, 작은 본문, 표와 표 옆 본문을
포함한다. 원본과 OCR 중간 결과는 `.gitignore`의 `output/` 아래에만 두었고,
저장소·GitHub 이슈·이 문서에는 원문 내용이나 이미지를 포함하지 않았다.

이 샘플에는 정답 Markdown이 없으므로 CER/TEDS 같은 정량 정확도는 계산하지
않고, 사용자가 보고한 실패 유형의 개선 여부를 항목별로 확인했다.

## 비교 결과

| 처리 | 관찰 결과 |
| --- | --- |
| `conservative` | 전체 본문은 비교적 안정적이나 워터마크 겹침 줄과 일부 번호 줄 누락 |
| `off` | 겹침 줄 일부가 보였지만 워터마크 간섭으로 전체 정확도 저하 |
| 임계값 150 + 2배 확대 | 부분 crop에서 겹침 줄 회수가 가장 안정적 |
| Phase 6 `text-safe` | 무채색 이진화·확대 후 원문 OCR 좌표를 보조 사용해 누락 구조 복구 |
| Phase 7 다중 OCR | 구조 입력을 보존하고 두 일반 OCR 후보로 깨진 text block만 교체 |
| Phase 8 표 인접 재조립 | 장기 셀 좌표 안의 원문 OCR 박스를 시각 행 단위로 다시 결합 |

`text-safe`는 색상 픽셀을 유지하고 무채색만 이진화한다. PP-Structure가 만드는
Markdown에서는 일반 OCR에 존재하는 줄도 누락될 수 있어, 이 모드에서만 일반
OCR 좌표를 함께 저장한다. 구조 결과에 없는 괄호형 번호 문단과 Note 줄만 원래
순서에 삽입하며 기존 번호는 중복하지 않는다.

## Phase 6 재평가

Phase 6은 Note·번호·전압 문구의 존재 여부만 확인했다. 이후 생성 Markdown 전체를
다시 비교하자 워터마크 겹침 주변에 깨진 일반 문장과 중복 문단이 남아 있었다.
따라서 해당 검증을 최종 합격으로 보지 않고 Issue #8에서 재작업했다.

## Phase 7 최종 확인

- 입력 1장으로 출력 2쪽 생성
- 옵션 생략 시 기본 `text-safe` 적용
- 구조 입력 `960×1080`, 복구 입력 `1920×2160` 분리
- 워터마크 겹침 구간의 Note 및 24V·48V·60V 일반 문장 회수
- Phase 6 결과의 알려진 깨짐 pattern과 Note 중복 제거
- 두 번째 쪽의 번호 1–11이 한 번씩 존재
- `3)`가 Markdown renderer에서 `3.`으로 바뀌지 않도록 `3\)`로 저장
- 표 옆 본문이 다섯 번째 병합 셀 또는 병합 셀 옆 셀로 흡수된 두 경우 모두
  본문을 표 밖으로 이동
- 전체 자동 테스트 55개 통과

## Phase 8 최종 확인

두 번째 쪽의 표 옆 소제목은 구조 OCR에서 큰 자간과 워터마크 때문에 숫자 뒤
한글 단어가 영문·숫자 조합으로 손상됐다. 같은 위치의 `text-safe` 원문 OCR에는
숫자 절 번호와 한글 단어가 각각 높은 신뢰도의 별도 박스로 정상 검출되어 있었다.

표 결과의 비정상 장기 셀 좌표 안에서 원문 OCR 박스를 선택하고, 수직 중심이
같은 박스를 좌→우로 결합하도록 후처리를 변경했다. 구조 셀 후보와 재조립 후보의
유사도·길이 비율·번호 문단 수를 검사하므로 왼쪽의 실제 표 데이터는 포함하지
않는다.

- 기존 Phase 7 OCR sidecar를 사용한 재조립에서 해당 소제목 정상 복구
- 문제의 영문·숫자 오인식 잔존 0건
- 표 옆의 두 정의 문단과 표 밖 후속 문장 유지
- Phase 7 대비 변경은 해당 표 인접 본문의 문자·띄어쓰기 교정으로 제한
- 전체 자동 테스트 56개 통과

- 원본 해상도 한계에서 남는 개별 문자 오류의 정답 기반 교정 기준
